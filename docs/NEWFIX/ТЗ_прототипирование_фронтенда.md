# ТЗ на доработку фронтенда — прототипирование

**Контекст:** ТЗ для дизайнера/прототиписта по итогам встречи с заказчиком (часть 1). Описаны конкретные правки на уровне UI: что добавляем, убираем, переносим, перестраиваем. Цель — собрать кликабельный прототип к завтрашнему дню для согласования с заказчиком.

**Роль в прототипе:** все экраны рассматриваем с точки зрения **заказчика** (роль «Заказчик/Клиент»), с пометками там, где сценарий пересекается с ролью бригадира.

**Принципы:**
- Телефонный экран — каждая единица вертикального пространства на счёт.
- «Три точки» везде = меню с действиями над элементом (в первую очередь «Редактировать»).
- Чат — глобальная сущность, доступна из любого экрана.
- Бюджет — частый сценарий, минимум кликов до быстрого добавления.

---

## 0. Глобальная навигация (нижняя панель)

### Сейчас
Нижняя панель содержит, среди прочего, вкладку **«Команда»**.

### Изменения

**УБРАТЬ из нижней панели:**
- Вкладка «Команда»

**ДОБАВИТЬ в нижнюю панель:**
- Вкладка **«Бюджет»** на освободившееся место

**ПЕРЕНЕСТИ:**
- «Команда» → внутрь раздела **«Чаты»** (отдельным верхним пунктом внутри Чатов)

### Состав нижней панели (целевое)
`Проекты` · `Бюджет` · `Чаты` · `[прочие]`

> **Замечание про чат:** глобальную/плавающую иконку чата НЕ делаем. Чат вызывается с конкретных экранов как статичная кнопка/иконка (см. карточку этапа — блок быстрых действий, экран шага — иконка в шапке).

## 1. Экран «Список проектов» (главная)

### Сейчас
- Карточки проектов идут списком.
- Нет фильтра и поиска.
- На карточке: адрес, просрочка, дата начала следующего этапа.

### Изменения

**ДОБАВИТЬ сверху над списком:**
- **Строка поиска** — по названию проекта (ключевое слово, например, «Лесная», «Бриг»)
- **Фильтр по статусам** — горизонтальные плашки-чипсы: `Все` · `Просрочен` · `По графику` · `Отставание` (мультивыбор или одиночный — на усмотрение, по умолчанию делаем одиночный)

**ДОБАВИТЬ на карточку каждого проекта (мини-дашборд):**
- Дней до дедлайна (число + подпись)
- Этапов выполнено / всего (например, «5/20»)
- **Этапов в активной работе** (отдельная метрика, например, «2 в работе») — критично, не путать с «осталось сделать»

**НЕ добавляем (зафиксировано отдельно):**
- ❌ Фоновую фотографию объекта на карточке — заказчик отказался

**Сохранить:**
- Адрес, просрочки, дата следующего этапа — оставляем как есть.

### Структура карточки проекта (целевое)
```
┌─────────────────────────────────────┐
│ Название проекта        [⋮]         │
│ Адрес                                │
│                                      │
│ [15 дней до дедлайна] [5/20 этапов] │
│ [2 в работе]                         │
│                                      │
│ Просрочка / По графику (шильдик)    │
└─────────────────────────────────────┘
```

## 2. Создание проекта

### Сейчас
- Шаги создания: название → даты → бюджет → описание → выбор этапов.
- Этапы добавляются, но порядок зафиксирован (нет перетаскивания).

### Изменения

**ДОБАВИТЬ на экране выбора этапов:**
- **Drag-and-drop** для смены очерёдности этапов (иконка-«гамбургер» слева от каждого этапа, перетаскивание удержанием)

**Остальное на этом флоу — оставляем как есть.** Основные правки появятся после нажатия «Создать проект» — см. экран карточки проекта.

## 3. Редактирование проекта (модалка/экран редактирования)

### Сейчас
- При изменении полей появляется кнопка «Сохранить».
- **Баг:** если изменить **только** дедлайн — кнопка «Сохранить» не активируется.

### Изменения

**ИСПРАВИТЬ:**
- Кнопка «Сохранить» должна активироваться при изменении **любого** поля, включая одиночное изменение дедлайна.

> *Это технический баг — для прототипа не критично, но в финальном ТЗ для разработки фиксируем явно.*

## 4. Карточка проекта (внутренний экран)

### Сейчас
**Структура сверху вниз:**
1. Большая иллюстрация-«домик» (занимает ~30% экрана)
2. Оранжевая плашка статуса («67%, 2 из 3, отставание»)
3. Квадратик «Прогресс» (дублирует пункт 2)
4. Дашборд: дней до дедлайна / этапов / 0 из 15 в работе
5. Бюджет (прогресс)
6. Раздел «Этапы проекта»
7. Нижние вкладки: `Этапы` `Команда` `…`

### Изменения

**ДОБАВИТЬ:**
- Кнопка/галочка справа вверху над «домиком» для **сворачивания иллюстрации**. По умолчанию — состояние **развёрнуто**, но визуально предусмотреть состояние «свёрнуто» (остаётся только тонкая полоска или вообще скрывается до повторного раскрытия).

**УБРАТЬ:**
- ❌ Квадратик «Прогресс» под оранжевой плашкой (дублирует данные сверху)
- ❌ Нижняя вкладка «Команда»

**ПЕРЕРАБОТАТЬ дашборд (вместо текущих 3-х показателей оставить 2):**
- `Дней до дедлайна`
- `Этапов выполнено / всего + N в работе` (объединить в один блок)

> *Оранжевая плашка статуса сверху остаётся — она информативна.*

**ПЕРЕНЕСТИ:**
- На место убранной вкладки «Команда» внизу → **«Бюджет»**

**ДОБАВИТЬ в блок «Этапы проекта»:**
- **Фильтр по статусам этапов** в виде горизонтальных плашек-чипсов сверху списка этапов:
  - `Все` · `В работе` · `На согласовании` · `На паузе` · `Без бригадира`
- Сортировка по умолчанию — хронологическая.

**ИСПРАВИТЬ (баг для пометки в прототипе):**
- Плашка «План на согласование, показать план целиком» должна быть кликабельной → ведёт на экран плана.

### Структура экрана (целевое)
```
┌─────────────────────────────────────┐
│ [🏠 иллюстрация]            [⌃ свернуть] │
├─────────────────────────────────────┤
│ 🟧 67% · 2 из 3 · Отставание        │
├─────────────────────────────────────┤
│ [15 дней до дедлайна]               │
│ [5/20 выполнено · 2 в работе]       │
├─────────────────────────────────────┤
│ Бюджет (прогресс-бар)               │
├─────────────────────────────────────┤
│ Этапы проекта                       │
│ [Все][В работе][На согл.][Пауза]…  │
│  • Этап 1 ...                       │
│  • Этап 2 ...                       │
├─────────────────────────────────────┤
│ [Этапы] [Бюджет] [...]              │ ← нижние вкладки (без «Команда»)
└─────────────────────────────────────┘
```

## 5. Экран «Бюджет проекта»

### Сейчас
- Много вкладок (этапы, материалы, выплаты и т.д.)
- Кнопка «Новая выплата» внизу.
- Жёсткое требование выбрать получателя (бригадира) для фиксации расхода.
- Заход в бюджет — неочевиден.

### Изменения — ПОЛНАЯ ПЕРЕРАБОТКА ЭКРАНА

**Новый флоу захода:**
1. Нижняя панель → `Бюджет`
2. Открывается список проектов пользователя
3. Тап на проект → попадаем **сразу** в экран бюджета этого проекта (без промежуточных шагов)

**Новая структура экрана «Бюджет проекта»:**

```
┌─────────────────────────────────────┐
│ ← Бюджет: [Название проекта]    [⋮]│
├─────────────────────────────────────┤
│ Мини-дашборд:                       │
│ Бюджет: 2 000 000 ₽                 │
│ Потрачено: 800 000 ₽ (40%)          │
│ — Работы: 200 000 / 500 000         │
│ — Материалы: 600 000 / 1 500 000    │
├─────────────────────────────────────┤
│ [ Выплаты за работу ][ Расходы ]    │ ← 2 вкладки
├─────────────────────────────────────┤
│ Хронологический список операций     │
│ по выбранной вкладке:                │
│  • 12.05 — Аванс бригадиру — 100к   │
│  • 10.05 — Цемент — 15к → Этап «...»│
│  • ...                               │
├─────────────────────────────────────┤
│ [+ Выплата]     [+ Расход]          │ ← 2 кнопки, делящие низ экрана пополам
└─────────────────────────────────────┘
```

**УБРАТЬ:**
- ❌ Все промежуточные вкладки кроме двух — `Выплаты за работу` и `Расходы по материалам`
- ❌ Кнопка «Новая выплата» внизу в одиночку
- ❌ Обязательное требование выбора получателя при фиксации расхода

**ДОБАВИТЬ:**
- 2 вкладки на одном уровне: **«Выплаты за работу» / «Расходы»**
- Внутри каждой вкладки — **хронологический список** операций
- Клик по записи в списке → проваливает на экран соответствующего этапа
- **2 быстрые кнопки внизу экрана** (делят ширину пополам):
  - `+ Выплата` — открывает модалку добавления выплаты
  - `+ Расход` — открывает модалку добавления расхода (см. ниже)

### 5.1. Модалка «Добавить расход» (флоу как CoinKeeper)

Прототипируем как быстрый bottom-sheet или fullscreen-модалку.

**Поля сверху вниз:**
1. **Фото чека** — большая кнопка-плейсхолдер «📷 Сфотографировать чек» (опционально, можно пропустить)
2. **Этап** — селектор «К какому этапу относится» (dropdown с этапами проекта)
3. **Категория** — селектор статьи расходов (dropdown)
4. **Название** — текстовое поле
5. **Сумма** — числовое поле
6. Кнопка **«Добавить»** внизу — крупная, на всю ширину

**Поведение после нажатия «Добавить»:**
- Расход появляется в списке вкладки «Расходы».
- Этот же расход **автоматически прикрепляется** к выбранному этапу (виден внутри этапа во вкладке «Бюджет этапа»).

### 5.2. Модалка «Добавить выплату»

Аналогично, но без обязательной привязки к человеку:
1. **Получатель** — опциональное поле (можно выбрать из команды или оставить пустым)
2. **Этап** — селектор
3. **Сумма**
4. **Комментарий** — опционально
5. Кнопка **«Добавить»**

## 6. Карточка этапа (внутренний экран этапа)

### Сейчас
**Структура сверху вниз:**
1. Пустое место (~15% экрана)
2. Название этапа («Подготовка»)
3. Статус
4. Цифры (шагов, фото, файлов)
5. Красная плашка «Бригадир не назначен» (если нет) — некликабельная
6. Вкладки внутри этапа: `Чек-лист` `Согласование` `Документы` `Чат` `[Бюджет?]`

### Изменения — ЗНАЧИТЕЛЬНАЯ ПЕРЕРАБОТКА

**ПОДНЯТЬ НАВЕРХ (на место пустого пространства):**
- Название этапа («Подготовка»)
- Иконка `⋮` (три точки) справа сверху → меню с действием **«Редактировать этап»**
- Статус — рядом с названием

**ПЕРЕРАБОТАТЬ блок цифр:**
- ❌ **УБРАТЬ:** количество фотографий, количество файлов (избыточная информация)
- ✅ **ОСТАВИТЬ:** счётчик шагов (выполнено / всего)
- ✅ **ДОБАВИТЬ:** счётчик доработок (`отправлено: 10 / выполнено: 5`)

**ДОБАВИТЬ блок «Команда этапа»** (под дашбордом цифр):
- Список построчно:
  - `Бригадир — Иван Петров`
  - `Мастер — Сергей Иванов`
  - `Мастер — Алексей Смирнов`
- Каждая строка кликабельна → открывает профиль с контактами
- Если бригадир не назначен → строка с красным шильдиком, **кликабельная** → ведёт на экран назначения бригадира из существующей команды проекта (НЕ форма ввода телефона)
- Иконка `+` для быстрого добавления члена команды

**ДОБАВИТЬ блок «Быстрые действия» под командой этапа:**

Две кнопки одного уровня, делящие ширину пополам:
- **`💬 Чат этапа`** — открывает чат, привязанный к этапу
- **`₽ Бюджет этапа`** — открывает экран бюджета этапа (см. раздел 12)

Эти кнопки **не плавающие, не FAB** — это статичный блок в иерархии экрана между «Командой этапа» и «Вкладками».

**ПЕРЕРАБОТАТЬ систему вкладок внутри этапа:**

**УБРАТЬ из вкладок:**
- ❌ Вкладка «Чат» (вынесена в блок быстрых действий выше)
- ❌ Вкладка «Бюджет этапа» (вынесена в блок быстрых действий выше, открывается отдельным экраном)

**ИТОГОВЫЙ набор вкладок этапа (4 штуки):**

| # | Вкладка | Что внутри |
|---|---------|------------|
| 1 | **Чек-лист** | Шаги этапа, хронология |
| 2 | **Согласования** | Косяки и рекламации (шильдик с числом открытых) |
| 3 | **Документы** | Фото/документы с фильтром и автогруппировкой |
| 4 | **Заявки** | Список заявок на материалы по этапу |

### Структура экрана этапа (целевое)
```
┌─────────────────────────────────────┐
│ ← Подготовка · 🟢 В работе      [⋮]│ ← название, статус, меню — наверху
├─────────────────────────────────────┤
│ Шагов: 3/5 · Доработок: 2/5         │ ← полезные счётчики
├─────────────────────────────────────┤
│ Команда этапа                       │
│  👤 Бригадир — Иван П.              │
│  👤 Мастер — Сергей И.              │
│  [+ Добавить]                        │
├─────────────────────────────────────┤
│ [ 💬 Чат этапа ] [ ₽ Бюджет этапа ]│ ← 2 быстрые кнопки
├─────────────────────────────────────┤
│ [Чек-лист][Согл.][Документы][Заявки]│ ← 4 вкладки
├─────────────────────────────────────┤
│ (содержимое выбранной вкладки)      │
└─────────────────────────────────────┘
```

## 7. Вкладка «Чек-лист» (внутри этапа)

### Сейчас
- Список шагов.
- Багов несколько: шаги не добавляются/не сохраняются, кнопка «Отправить на согласование» / «Запустить этап» отсутствует.

### Изменения

**ДОБАВИТЬ:**
- Кнопка **«+ Добавить шаг»** внизу списка
- В меню «⋮» каждого шага: `Редактировать`, `Удалить`, `Отправить на согласование`
- Кнопка **«Запустить этап»** / **«Отправить на согласование»** — на уровне этапа (например, плавающая внизу экрана или над списком шагов). Активна только при выполнении условий (бригадир назначен и т.д.)

**Хронология:**
- Каждый шаг показывает: кто отметил, статус (в работе / на согласовании / согласовано / на доработке), дату последнего действия
- Шильдик «На согласование» — рядом с теми шагами, что отправлены на согласование

## 8. Шаг (экран внутри Чек-листа)

### Сейчас
- Большое поле «Отчёт» / «Описание хода работы» — занимает много места
- Загрузка фото
- Нет видео

### Изменения

**ДОБАВИТЬ:**
- **Поддержка видео** в загрузке (наряду с фото)
- **Хронологический поток** медиа (фото и видео в порядке загрузки, без жёсткого разделения «до/после»)
- Для каждого медиа — подпись: кто загрузил, когда, к чему относится (если есть)
- **Кнопка «Перейти в чат этапа»** — иконка в шапке шага рядом с кнопкой «назад» (статичная, не плавающая). Ведёт в тот же чат этапа, который доступен с экрана этапа.

**Кнопки действий внизу шага (для роли «Заказчик» при статусе «На согласовании»):**
- `✅ Согласовать` (зелёная)
- `↩️ Отправить на доработку` (нейтральная/оранжевая)

**Важно:** кнопка `Отправить на доработку` **остаётся доступной даже после согласования шага** (на случай выявленных позже косяков — «стенка лопнула через неделю»).

**ПЕРЕРАБОТАТЬ блок «Отчёт»:**
- Сделать **сворачиваемым**
- По умолчанию **свёрнут**
- Визуальная индикация:
  - **Зелёный/активный** заголовок «Отчёт» — если внутри есть содержимое
  - **Серый/неактивный** — если пусто
- Тап по заголовку → раскрывается

### Структура экрана шага (целевое)
```
┌─────────────────────────────────────┐
│ ← Шаг: Укладка плитки в санузле   💬│ ← кнопка чата
│ Статус: На согласовании             │
├─────────────────────────────────────┤
│ ▶ Отчёт (свёрнут, серый если пусто)│ ← сворачиваемый
├─────────────────────────────────────┤
│ Медиа (хронологически):             │
│  📷 12.05 14:23 — Сергей И.         │
│  📷 12.05 14:25 — Сергей И.         │
│  🎥 12.05 14:30 — Сергей И.         │
│  [+ Добавить фото/видео]            │
├─────────────────────────────────────┤
│ [✅ Согласовать] [↩️ На доработку]  │
└─────────────────────────────────────┘
```

### 8.1. Флоу «Отправить на доработку» (рекламация)

При нажатии `↩️ Отправить на доработку`:
1. Открывается экран/модалка «Добавление косяков»
2. Пользователь добавляет фото (несколько) — каждое фото = отдельный косяк (или один косяк с несколькими фото — уточнить с заказчиком, в прототипе показываем оба варианта)
3. Опциональный комментарий
4. Кнопка «Отправить»
5. У бригадира появляется список косяков в его роли + уведомление в звоночке
6. Когда бригадир исправляет, делает фото «после» → косяк закрывается, остаётся пара «до/после» внутри хронологии

## 13. Глобальные UX-паттерны (применить во всём прототипе)

### 13.1. Иконка «⋮» (три точки)
**Везде, где присутствует** — вызывает контекстное меню с действиями. Минимальный набор:
- `Редактировать`
- `Удалить` / `Архивировать`
- (опционально) специфичные действия для контекста

### 13.2. Кнопка чата
**Не плавающая (не FAB).** Размещается как обычный элемент в иерархии экрана:
- **Карточка проекта** — кнопка/иконка вверху или в блоке быстрых действий
- **Карточка этапа** — кнопка в блоке быстрых действий под командой этапа (рядом с кнопкой «Бюджет этапа»)
- **Экран шага** — иконка в шапке шага (рядом с кнопкой «назад»), ведёт в чат этапа

### 13.3. Красные плашки-предупреждения
Всегда кликабельны → ведут к решению проблемы. Примеры:
- «Бригадир не назначен» → экран назначения бригадира
- «План на согласование» → экран плана

### 13.4. Имена пользователей
Везде, где отображается человек, — показываем **имя**, а не «Участник». В прототипе использовать ФИО или имя+фамилию.

### 13.5. Архивирование
«Архивировать» = soft-delete. В прототипе можно не делать отдельный раздел «Архив», но в меню «⋮» проекта пункт `Архивировать` должен присутствовать.

## 14. Сценарии для демо в кликабельном прототипе

Для записи видео-обзора закладываем минимум следующие сквозные сценарии:

1. **Создание проекта** → добавление этапов с перетаскиванием → попадание в карточку проекта
2. **Поиск и фильтрация** на главном экране
3. **Карточка проекта** → сворачивание иллюстрации → фильтр этапов «В работе»
4. **Заход в бюджет** через нижнюю панель → выбор проекта → добавление расхода с чеком → проверка, что расход появился в нужном этапе
5. **Этап** → назначение бригадира из существующей команды (НЕ ввод телефона) → запуск этапа
6. **Шаг** → загрузка фото мастером (как мастер) → согласование (как заказчик) → отправка на доработку → добавление косяков → исправление (как бригадир)
7. **Заявка на материалы** — бригадир добавляет в шаг → отображение в общей вкладке «Заявки»
8. **Документы** → переключение «Фото/Документы» → группировка по шагам
